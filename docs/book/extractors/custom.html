neo4j_eio User Guide

Custom Extractors

Build your own extractors to map Neo4j records into domain types with precise validation and helpful errors. This page shows patterns that match the current Extract and Record APIs.

Use Extract.field with Record.at_*

  • Extract.field key decoder turns any Record.at_* function into an extractor component.
open Neo4j_eio
open Extract

type account = { id: int64; name: string; active: bool }

let account_extractor =
  let+ id = field "id" Record.at_int
  and+ name = field "name" Record.at_text
  and+ active = field "active" Record.at_bool in
  { id; name; active }

Decode lists with element decoders

  • Leverage Record.at_list element_exact via Extract.list key element_exact.
let tags_extractor = list "tags" Record.exact_text

Optional with defaults

  • Combine maybe_* and default for robust schemas.
let person_extractor =
  let+ name = text "name"
  and+ age = int "age"
  and+ email = (maybe_text "email" >>| Option.value ~default:"-") in
  (name, age, email)

Map to domain types

  • Map from Value shapes to your types once, then reuse.
module Domain = struct
  type point = { x: float; y: float }
end

let point_extractor =
  let+ p = point2d "pt" in
  { Domain.x = p.x; y = p.y }

Pipeline integration (fluent Cypher)

  • When using the Cypher fluent API, prefer Cypher.extract extractor query to apply an Extract.t to each record; decode errors are surfaced as Error.ClientError with a helpful message.
let query =
  Cypher.query "RETURN 1 AS id, 'alice' AS name"
  |> Cypher.extract Extract.(
       let+ id = int "id"
       and+ name = text "name" in
       (id, name))

Error reporting

  • Extract.run returns ('a, Record.decode_error) result. Pretty‑print with Record.pp_decode_error for actionable messages.

Best practices

  • Always alias fields in RETURN for stable keys.
  • Keep extractors near their query definitions for locality, or centralize in a module when used across queries.
  • Compose small extractors; avoid monolithic decoders.
