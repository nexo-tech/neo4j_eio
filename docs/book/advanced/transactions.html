neo4j_eio User Guide

Transactions (Session API)

This guide shows explicit transaction management using the Session API. It reflects the current implementation in ocaml/src/session.ml.

Key operations

  • Session.begin_transaction : t -> (unit, Error.t) result
  • Session.commit : t -> (unit, Error.t) result
  • Session.rollback : t -> (unit, Error.t) result
  • Session.transact : t -> (t -> ('a, Error.t) result) -> ('a, Error.t) result (functional helper)

Explicit control

open Neo4j_eio

Eio_main.run @@ fun env ->
  let cfg = Config.of_env () in
  Eio.Switch.run @@ fun sw ->
    match Session.with_session ~sw ~net:env#net cfg (fun s ->
      match Session.begin_transaction s () with
      | Error e -> Error e
      | Ok () ->
          (* Run queries inside the transaction *)
          (match Query_builder.execute
                   (Query_builder.raw "CREATE (n:Tmp {value: 1}) RETURN 1 AS ok") s with
           | Error e ->
               (* Roll back on error *)
               let _ = Session.rollback s in
               Error e
           | Ok _ ->
               (* Commit on success *)
               Session.commit s)
    ) with
    | Ok () -> ()
    | Error e -> Printf.eprintf "tx failed: %s\n" (Error.to_string e)

Functional helper

  • Session.transact s (fun s -> ...) begins a transaction, runs your function, commits on Ok and rolls back on Error.
let result = Session.transact s (fun s ->
  match Query_builder.execute (Query_builder.raw "RETURN 1 AS ok") s with
  | Ok [r] -> (match Record.at_int r "ok" with Ok 1L -> Ok () | _ -> Error (Error.ClientError {code="Client.BadDecode"; message="expected 1"}))
  | Ok _ -> Error (Error.ClientError {code="Client.BadShape"; message="expected one row"})
  | Error e -> Error e)

Failure and reset behavior

  • Inside a transaction, automatic RESET on FAILURE is suppressed; call Session.rollback to clear failed state.
  • Outside a transaction, the driver auto‑issues RESET on FAILURE.

Tips

  • Keep multi‑step mutations inside one transaction for atomicity.
  • For read‑only flows, you can skip explicit transactions unless you need snapshot semantics.
  • Prefer Query Builder + Session.run_records for named fields; decoding is simpler with Record.at_*.
